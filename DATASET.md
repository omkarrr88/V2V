## 1. Data Availability Statement

### 2.3 SUMO network conversion

The OSM file is converted to a SUMO microscopic-traffic network using Eclipse SUMO `netconvert v1.24.0` with the projection `+proj=utm +zone=43 +ellps=WGS84 +datum=WGS84 +units=m +no_defs`. The exact command (also embedded in the network file's `netconvertConfiguration` header) is:

```
netconvert --osm-files atal.osm \
           --output-file atal.net.xml \
           --proj.utm \
           --geometry.remove \
           --tls.discard-simple --tls.join \
           --tls.guess-signals --tls.default-type actuated \
```

## 3. Synthetic Dataset — Generation Process

All vehicle telemetry, risk scores, alerts, and ground-truth labels are generated by Eclipse SUMO. The pipeline has five stages, all of which are deterministic under random seed 42 (set in NumPy, Python `random`, and the SUMO `--seed` CLI flag).

### 3.1 Stage 1 — Traffic demand

Two route files are used as input to the simulation. Both are committed to the repository.

| File | Vehicles | Generated by | Purpose |
|------|---------:|--------------|---------|
| `Maps/atal_v2v.rou.xml` | 2,400 | SUMO `randomTrips.py` → `duarouter` (seed 42, 0–360 s departure window, 1.5 s headway) | Background ambient traffic |
| `Maps/atal_bridge_scenarios.rou.xml` | 8,059 | `Scripts/gen_bridge_routes.py` (seed 42) | Forced blind-spot pairs, platoons, and saturation traffic |

The 8,059 forced-blind-spot vehicles are produced in four phases:

| Phase | Description | Vehicles |
|-------|-------------|---------:|
| 1. Blind-spot pairs (chaos engine) | Slow leader on lane 0 + fast catcher on lane 1, repeated every 3 s on every multi-lane edge | ≈ 7,000 |
| 2. Cross-map saturation | 150 random origin-destination tours covering the whole network | 150 |
| 3. High-density platoons | 40 packs of 6 cars at 0.5 s headway | 240 |
| 4. 360° boundary inflow | One vehicle per boundary edge every 10 s | ≈ 670 |
| **Total** | | **8,059** |

### 3.2 Stage 2 — Vehicle fleet composition

The synthetic fleet consists of three vehicle classes representative of mixed Indian urban traffic. Definitions are taken verbatim from the route-file `<vType>` declarations:

| Class | Length (m) | Width (m) | Max speed | Acceleration (m/s²) | Deceleration (m/s²) | Mix |
|-------|-----------:|----------:|----------:|--------------------:|--------------------:|----:|
| Sedan | 4.5 | 1.8 | 33.33 m/s (120 km/h) | 2.6 | 4.5 | 65 % |
| SUV | 4.8 | 2.0 | 30.56 m/s (110 km/h) | 2.2 | 4.0 | 25 % |
| Truck | 12.0 | 2.5 | 25.0 m/s (90 km/h) | 1.0 | 3.0 | 10 % |

Two synthetic micro-networks (used only for the TSV and HNR scenario isolation experiments) define their own vehicle types verbatim:

```xml
<!-- scenario_tsv.rou.xml (4-arm signalised intersection) -->
<vType id="compliant" minGap="2.0" accel="2.6" decel="4.5" maxSpeed="15.0"/>
<vType id="violator"  minGap="1.0" accel="3.2" decel="4.5" maxSpeed="20.0"/>

<!-- scenario_hilly.rou.xml (5×5 grid with short edges) -->
<vType id="passenger"  minGap="2.5" accel="2.0" decel="4.5" maxSpeed="15.0" sigma="0.5"/>
<vType id="aggressive" minGap="1.0" accel="3.0" decel="5.0" maxSpeed="20.0" sigma="0.2"/>
<vType id="truck"      minGap="3.0" accel="1.0" decel="3.0" maxSpeed="10.0" length="12.0"/>
```

### 3.3 Stage 3 — Microscopic simulation

The driver script `Scripts/v2v_bsd_simulation.py` runs SUMO via `libsumo`/TraCI and produces the primary dataset. Each simulated vehicle broadcasts a 5-field Basic Safety Message at 10 Hz; the receiver applies a realistic GPS-noise model and a 2-state Markov packet-loss channel.

| Simulation parameter | Value | Reference |
|----------------------|-------|-----------|
| Simulator version | Eclipse SUMO 1.19+ (published run: sumolib 1.26.0 with `libsumo`) | sumo.dlr.de |
| Step length | 0.1 s (10 Hz update rate) | atal_v2v.sumocfg |
| Simulated time | 360 s (3,600 steps) | CLI default |
| Random seed | 42 | applied to NumPy, Python `random`, SUMO |
| BSM frequency | 10 Hz | SAE J2945/1 standard |
| Communication range | 300 m | DSRC nominal |
| Max simultaneous vehicles | 163 | observed peak |
| Logging cadence | every 0.2 s per active ego | v2v_bsd_simulation.py |
| GPS noise model | 1st-order Gauss–Markov, σ = 1.5 m, τ = 10 s | per-vehicle correlated walk |
| Channel model | Gilbert–Elliott (`p_G→B`=0.01, `p_B→G`=0.10, PLR_GOOD=0.01, PLR_BAD=0.50) | Gilbert (1960) |
| Background packet drop | 5 % | nominal |

The SUMO main configuration file (`Maps/atal_v2v.sumocfg`) used for the published run, verbatim:

```xml
<configuration>
    <input>
        <net-file value="atal.net.xml"/>
        <route-files value="atal_v2v.rou.xml,atal_bridge_scenarios.rou.xml"/>
    </input>
    <time>
        <begin value="0"/>
        <end value="3600"/>
        <step-length value="0.1"/>
    </time>
    <processing>
        <lateral-resolution value="0.8"/>
        <collision.action value="warn"/>
        <collision.mingap-factor value="0"/>
        <default.speeddev value="0.1"/>
        <random-depart-offset value="3"/>
        <ignore-route-errors value="true"/>
    </processing>
</configuration>
```

### 3.4 Stage 4 — Ground-truth labelling

Labels are derived deterministically from the BSM telemetry; **no human annotation is involved**. The labelling rule (from `Scripts/bsd_utils.py`) is:

```
A row is POSITIVE  ⇔  ground_truth_collision = 1  (SUMO-reported physical collision)
                  OR  (num_targets > 0
                       ∧ ego.speed > 2.0 m/s
                       ∧ target inside blind-spot zone
                       ∧ (max_gap < 1.0 m  OR  TTC_proxy < 2.0 s))

  where  TTC_proxy = max_gap / max(rel_speed, 0.5)
```

Constants used (committed at the top of `bsd_utils.py`):

```python
GT_GAP_CRITICAL      = 1.0     # m   — longitudinal gap below which event is positive
GT_TTC_CRITICAL      = 2.0     # s   — kinematic TTC proxy threshold
GT_MIN_REL_SPEED     = 0.5     # m/s — division-by-zero guard
GT_MIN_EGO_SPEED     = 2.0     # m/s — ignore stationary egos
GT_MAX_POSITIVE_RATE = 0.15    # sanity cap (15 %)
```

Label distribution on the published dataset:

| Label class | Count | Percentage |
|-------------|------:|-----------:|
| Negative (SAFE) | 142,586 | 97.63 % |
| Positive (near-miss or collision) | 3,465 | 2.37 % |
| └─ SUMO-reported physical collisions | 27 | 0.018 % |
| └─ Kinematic near-miss proxies | 3,438 | 2.354 % |

### 3.5 Stage 5 — AI training table

The training table consumed by `Scripts/train_ai_model.py` is derived from the primary CSV through:

1. A stratified 75 / 25 train/test split (`random_state = 42`).
2. Injection of **300 synthetic CRITICAL rows into the training partition only** (sampled from a hardcoded uniform distribution; see §4.7) to compensate for the rarity of severe events. The test partition is never touched.
3. **SMOTE oversampling** to ≥ 3,000 CAUTION, ≥ 2,000 WARNING, ≥ 500 CRITICAL.
4. XGBoost training with: `n_estimators=200`, `max_depth=6`, `learning_rate=0.1`, `subsample=0.8`, `colsample_bytree=0.8`, `min_child_weight=3`, `gamma=0.1`, `reg_alpha=0.1`, `reg_lambda=1.0`, `objective=multi:softprob`, `num_class=4`, `random_state=42`.
5. Evaluation on the untouched 25 % holdout **plus** 5-fold `TimeSeriesSplit` cross-validation.

| Partition | Rows | Composition |
|-----------|------:|-------------|
| Holdout test set (untouched) | 4,757 | Stratified 25 % of original data |
| Training set after SMOTE + 300 synthetic CRITICAL | 19,375 | SMOTE-oversampled minority classes |

The 15 features used by the XGBoost classifier are listed in §4.4 below. **Scenario flags (TSV/HNR) are deliberately excluded** from the feature set so the model generalises by physical behaviour rather than memorising scenario tags.

## 6. Suggested Paragraph for the Manuscript

> **Data Availability.** This study uses no proprietary, restricted, or third-party benchmark dataset. The road-network geometry of the Atal Setu corridor, Navi Mumbai, India, was obtained from OpenStreetMap (© OpenStreetMap contributors, ODbL v1.0; https://www.openstreetmap.org/) on 26 September 2025 within the bounding box (lat 18.99201–19.00297° N, lon 72.84648–72.86214° E) and converted to a SUMO microscopic-traffic network using `netconvert` v1.24.0. All vehicle trajectories, Basic Safety Messages (BSMs), kinematic near-miss labels, ablation tables, and trained model artifacts were generated by the Eclipse SUMO 1.19+ microscopic simulator under the deterministic random seed 42 using the open-source scripts in this repository: https://github.com/omkarrr88/V2V. The complete synthetic dataset (`Outputs/bsd_metrics.csv`, 146,051 rows × 45 columns), the trained XGBoost model (`Outputs/bsd_xgboost_model.json`), the alert log (`Outputs/bsd_alerts.csv`), and the ablation/sensitivity tables are committed to the same repository. No human-subject data, no personal data, and no real-vehicle telemetry were used.
